Set up the Postgres database for a clinic assistant.

This folder is a new Python project. Use uv with Python 3.12, and add `psycopg[binary]` and `python-dotenv`. The database is Postgres on Neon, and the connection string is already in `.env` as `DATABASE_URL`. Never print or log it, and make sure `.env` is in `.gitignore`.

Create three files:

- `db/schema.sql` creates the tables. It starts by dropping them, so we can run it again for a clean start.
- `db/setup.py` runs `schema.sql`, then loads the starting data below. We run it with `uv run db/setup.py`. At the end it prints how many rows each table has.
- `db/queries.sql` holds a few queries we can run in Neon's SQL editor to look at the data: all users with their insurance plan, all doctors, Dr. Anita Rao's open slots this week, and all appointments with the patient's name, the doctor's name and the slot time.

## Rules for every table

- `id`: a bigint generated by Postgres (`generated always as identity`). Never hard-code an id. To link rows, look the id up by email, code or name.
- `created_at`, `created_by`, `updated_at`, `updated_by`, `void_sw`:
  - `created_at` and `updated_at` default to now. One shared trigger sets `updated_at` on every update.
  - `created_by` and `updated_by` point to `users.id`.
  - `void_sw` is a boolean, default false. A void row was a mistake and is treated as deleted.
- Unique rules apply only to rows where `void_sw = false`.

## Tables

- `users`: patients and admins.
  - `role` (patient or admin), `full_name`, `email` (unique), `phone`.
  - `date_of_birth`, `insurance_plan_id` (points to `insurance_plans`) and `insurance_member_id`. These are empty for admins.
  - `password_hash`, empty for now.
- `doctors`: `full_name`, `speciality_code`, `speciality`.
- `doctor_calendar`: one row per 30-minute slot.
  - `doctor_id`, `starts_at`, `ends_at`, `status` (open, booked or leave).
  - A doctor can't have two slots that start at the same time.
- `insurance_plans`: `code` (unique), `name`, `accepted` (boolean).
- `user_appointments`:
  - `booking_code` is unique and generated by Postgres, like `APT-770460`.
  - `user_id`, `calendar_id`, `reason`, `status` (booked or cancelled).
- `user_intake`: one row per intake form.
  - `user_id`.
  - `appointment_id`, empty until the appointment is booked.
  - `answers`: jsonb keyed by a short question code, like `{"allergies": "penicillin"}`.
- `user_facts`: `user_id`, `fact`.
- `user_preferences`: `user_id`, `preference`.
- `user_notes`: `user_id`, `note`.
- `user_visits`: `user_id`, `appointment_id`, `summary`.
- `sent_emails`: `user_id`, `appointment_id`, `to_email`, `subject`, `body`.
